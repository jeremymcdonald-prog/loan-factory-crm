# Edge Case Scenarios

## Purpose

These scenarios test unusual but realistic usability risks. They are not implementation requirements. They help product, design, QA, training, and leadership decide whether TERA+ is understandable when the workflow is not clean.

| Scenario ID | Edge case | Primary personas | Product OS IDs | Task | Starting point | Expected path | What success looks like | Where users may get stuck | What should be measured | Pass or fail criteria |
|---|---|---|---|---|---|---|---|---|---|---|
| SCN-EDGE-001 | User cannot tell if work saved | LO-VET-NTS-05, BOR-LOWTECH-13, LC-NEW-NTS-01 | TERA-LEAD, TERA-DOCS, TERA-STATUS | Confirm save state after a demo update. | User saves lead/status/document update. | Look for confirmation, history entry, or saved status. | User confidently knows work saved. | Missing confirmation or subtle status change. | Confidence, repeat submissions, duplicate records. | Pass if user does not re-submit; fail if duplicate entry occurs. |
| SCN-EDGE-002 | Role block appears during urgent task | LC-EXP-TS-04, PR-NEW-TS-02, IB-TL-NTS-02 | TERA-RBAC, TERA-CONDITIONS | Recover from blocked action. | User tries restricted action during demo urgency. | Read block, route to correct owner, preserve context. | User knows why blocked and what to do next. | Block sounds like error or dead end. | Recovery time, confidence, routed task quality. | Pass if routed correctly; fail if user abandons or bypasses. |
| SCN-EDGE-003 | Stale dashboard data | IB-TL-TS-01, IB-BD-RETENTION-14, PR-EXP-TS-04 | TERA-DASH, TERA-STATUS | Recognize stale demo data. | Dashboard metric has older timestamp than file detail. | Notice freshness indicator, open detail, avoid wrong decision. | User understands data freshness. | Timestamp hidden or unclear. | Stale-data awareness, decision quality. | Pass if user checks source before acting; fail if stale metric drives action. |
| SCN-EDGE-004 | Same borrower name in two demo files | LO-MID-NTS-03, LC-NEW-TS-02, PR-NEW-NTS-01 | TERA-LEAD, TERA-DOCS | Select correct demo record. | Search returns two similar fake names. | Use non-PII demo differentiators such as file ID, LO owner, stage. | Correct record is opened. | User relies on name only. | Error rate, recovery, search clarity. | Pass if correct record chosen; fail if document/status is added to wrong file. |
| SCN-EDGE-005 | Wrong document category selected | BOR-MOBILE-12, LC-NEW-NTS-01, PR-EXP-TS-04 | TERA-DOCS, TERA-CONDITIONS | Correct wrong document label. | Fake upload is assigned wrong category. | Find document, update label or route review, preserve audit trail. | Corrected category and review state are visible. | User cannot edit or route correction. | Recovery, confidence, audit clarity. | Pass if correction is traceable; fail if wrong label remains unowned. |
| SCN-EDGE-006 | Borrower starts application on mobile and finishes later | BOR-MOBILE-12, BOR-FTB-01 | TERA-APP, TERA-1003 | Resume incomplete application. | Demo application is half complete on mobile. | Return to application, find progress, continue without retyping. | Progress persists and next required section is clear. | Lost progress or unclear resume point. | Recovery, duplicate entry, mobile usability. | Pass if user resumes successfully; fail if progress appears lost. |
| SCN-EDGE-007 | Borrower asks for final approval wording too early | BOR-FHA-03, LO-NEW-NTS-01, IB-COMP-ADCOMM-12 | TERA-AUS, TERA-COMMS | Choose safe approval wording. | Demo borrower asks if approved after AUS placeholder. | Use safe draft language and route if needed. | Message avoids final approval claim. | User may equate AUS with approval. | Compliance language, confidence. | Pass if wording is safe; fail if final approval is implied. |
| SCN-EDGE-008 | Agent requests private borrower detail | REA-LISTING-04, REA-COMM-11, LO-MID-TS-04 | TERA-COMMS, TERA-RBAC | Respond with privacy-safe update. | Demo agent asks for sensitive borrower detail. | Use agent-safe status, decline/private boundary politely. | Update is useful without exposing private data. | Pressure to overshare. | Privacy boundary, communication clarity. | Pass if no sensitive detail is shared; fail if private info appears. |
| SCN-EDGE-009 | Opt-out or DNC state affects communication | IB-COMP-ADCOMM-12, IB-MKT-AUTO-10, LO-MID-NTS-03 | TERA-COMMS, TERA-RBAC | Avoid communication to opted-out demo contact. | Demo contact has opt-out flag. | Open communication workflow, notice flag, stop or route review. | No outbound communication occurs. | Flag too subtle or hidden. | Flag visibility, critical error prevention. | Pass if send is blocked/avoided; fail if message appears sendable. |
| SCN-EDGE-010 | AI summary conflicts with document label | IB-UW-TS-06, PR-EXP-TS-04, IB-COMP-POLICY-11 | TERA-DOCS, TERA-AUS | Resolve conflict between AI summary and source label. | Demo AI summary says doc type A, label says doc type B. | Open source document/audit, flag conflict, route manual review. | Conflict is not accepted blindly. | User over-trusts AI. | AI trust, evidence lookup, review routing. | Pass if manual review is triggered; fail if AI summary is accepted without evidence. |
| SCN-EDGE-011 | User loses connection during upload | BOR-MOBILE-12, BOR-LOWTECH-13 | TERA-DOCS | Recover interrupted upload. | Fake upload is interrupted. | Reopen upload area, see failed/pending state, retry safely. | User knows upload did not complete and avoids duplicate confusion. | Failure state unclear. | Recovery, duplicate upload, confidence. | Pass if retry is clear; fail if user cannot tell what happened. |
| SCN-EDGE-012 | Notification points to item user cannot access | REA-TEAMLEAD-07, IB-BD-RETENTION-14, LC-EXP-NTS-03 | TERA-NOTIF, TERA-RBAC | Handle inaccessible linked item. | Demo notification opens restricted item. | Show reason and route to authorized owner. | User understands access boundary and next step. | Notification feels broken. | Recovery, confidence, permission clarity. | Pass if no restricted data leaks and route is clear; fail if dead end. |
| SCN-EDGE-013 | Multiple people edit same demo note/task | LO-MID-TS-04, LC-EXP-TS-04, PR-EXP-TS-04 | TERA-COMMS, TERA-CONDITIONS | Understand latest update. | Demo note/task has two recent edits. | Open history, identify current owner and latest action. | User can tell which update is current. | History order or overwritten notes. | Confusion, audit trail clarity. | Pass if latest action is identified; fail if user acts on stale note. |
| SCN-EDGE-014 | Borrower needs translation-ready guidance | BOR-ITIN-08, BOR-FOREIGN-09, BOR-LOWTECH-13 | TERA-APP, TERA-DOCS, TERA-COMMS | Understand simple instruction without idioms. | Demo borrower views instruction with mortgage jargon. | Use plain-language alternate text or help content. | Borrower knows what to upload or answer. | Idioms, acronyms, long paragraphs. | Comprehension, help needed, completion rate. | Pass if user completes task; fail if wording blocks progress. |
