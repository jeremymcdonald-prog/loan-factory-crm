# Stress Test Scenarios

## Purpose

These scenarios test whether TERA+ stays understandable under pressure. Use fake/demo data only. Do not use real borrower records, real pricing, real AUS findings, real lender credentials, real documents, production writes, or real borrower-visible communications.

| Scenario ID | Stress case | Primary personas | Product OS IDs | Task | Starting point | Expected path | What success looks like | Where users may get stuck | What should be measured | Pass or fail criteria |
|---|---|---|---|---|---|---|---|---|---|---|
| SCN-STRESS-001 | Friday afternoon closing issue | LO-VET-NTS-05, PR-EXP-NTS-03, LC-EXP-TS-04, REA-SPEED-10, BOR-URGENT-14 | TERA-DASH, TERA-CONDITIONS, TERA-COMMS, TERA-NOTIF | Identify the closing blocker and route the next action. | Demo file shows closing soon with one unresolved condition. | Open urgent alert, review condition, assign owner, draft internal update only. | Correct blocker, owner, and next action are visible with timestamp. | Panic, duplicate tasks, unclear owner, or unsafe external update. | Time to identify blocker, duplicate tasks, confidence, escalation clarity. | Pass if blocker is correctly routed without external send; fail if wrong owner, duplicate escalation, or private data exposure occurs. |
| SCN-STRESS-002 | Borrower uploaded wrong documents | BOR-LOWTECH-13, LC-NEW-NTS-01, PR-NEW-NTS-01 | TERA-DOCS, TERA-CONDITIONS, TERA-COMMS | Recover from wrong fake document upload. | Demo borrower uploads incorrect placeholder document. | Identify mismatch, mark pending/rejected per demo workflow, request correct item through internal draft. | Wrong document is not accepted and borrower next step is clear. | User may clear condition, delete evidence, or shame/confuse borrower. | Recovery steps, error rate, clarity of request. | Pass if wrong document remains traceable and correct request is created; fail if condition is cleared or source is lost. |
| SCN-STRESS-003 | Duplicate lead created | LO-NEW-TS-02, LC-EXP-TS-04, IB-TL-TS-01 | TERA-LEAD, TERA-DASH, TERA-RBAC | Detect and recover from duplicate demo lead. | Two demo leads share same fake contact details. | Open duplicate warning or dashboard, merge/route according to allowed role, preserve notes. | Duplicate is identified and safe recovery path is clear. | Role cannot merge, warning is unclear, or notes appear lost. | Duplicate detection, recovery confidence, data loss risk. | Pass if user resolves or routes duplicate without losing history; fail if duplicate remains unowned. |
| SCN-STRESS-004 | AUS changes from approve to refer | LO-MID-TS-04, PR-EXP-TS-04, IB-UW-TS-06 | TERA-AUS, TERA-STATUS, TERA-COMMS | Update understanding after demo AUS status changes. | Demo AUS status changes from approve/eligible placeholder to refer placeholder. | Open AUS history, review change, update internal note, avoid final approval language. | User understands status changed and borrower-facing language must be careful. | Users may overstate approval or miss history. | Status comprehension, compliance-safe language, history lookup. | Pass if update is routed internally with safe wording; fail if final approval is implied. |
| SCN-STRESS-005 | Appraisal comes in low | LO-VET-TS-06, PR-EXP-NTS-03, REA-LISTING-04 | TERA-STATUS, TERA-COMMS, TERA-DOCS | Review low-appraisal demo event and route update. | Demo appraisal placeholder shows value issue. | Open file status, identify affected parties, draft internal next-step note. | Status and next action are clear without exposing sensitive borrower details. | Users may disclose private details to agent or choose wrong status. | Privacy control, status clarity, escalation path. | Pass if update is privacy-safe and routed; fail if sensitive borrower data is shared. |
| SCN-STRESS-006 | Rate lock expiring | LO-MID-NTS-03, LC-EXP-NTS-03, PR-EXP-TS-04 | TERA-NOTIF, TERA-PRICING, TERA-DASH | Act on demo lock-expiration warning without quoting real pricing. | Dashboard shows fake lock-expiration alert. | Open alert, verify owner, create internal pricing/lock follow-up. | User knows urgency and avoids final rate language. | Users may treat alert as final pricing or miss owner. | Time to action, pricing-risk language, owner clarity. | Pass if internal follow-up is created; fail if real/final pricing is entered. |
| SCN-STRESS-007 | Borrower changes jobs | BOR-COMPLEX-15, LO-MID-TS-04, PR-NEW-TS-02, IB-UW-NTS-05 | TERA-1003, TERA-AUS, TERA-CONDITIONS | Update demo employment change and identify downstream review. | Demo borrower reports job change before closing. | Open application, note change, flag AUS/income review, assign owner. | Employment change is captured and downstream review is clear. | Users may update one field but miss AUS/condition impact. | Missed downstream tasks, recovery, confidence. | Pass if income/AUS review is routed; fail if file status remains unchanged and unflagged. |
| SCN-STRESS-008 | Self employed income problem | BOR-SELFEMP-05, PR-EXP-TS-04, IB-UW-TS-06 | TERA-DOCS, TERA-AUS, TERA-CONDITIONS | Resolve income-review blocker with fake docs. | Demo self-employed file has income discrepancy placeholder. | Review docs, AUS/AI comparison if available, create condition or task. | Discrepancy is clearly documented and not hidden. | Users may over-trust AI or fail to link source docs. | Evidence trail, AI trust, condition accuracy. | Pass if source-backed blocker is linked; fail if unsupported summary drives decision. |
| SCN-STRESS-009 | Realtor demands update | REA-SPEED-10, LO-VET-NTS-05, LC-NEW-TS-02 | TERA-COMMS, TERA-RBAC, TERA-STATUS | Provide privacy-safe status under pressure. | Demo agent requests urgent file details. | Open agent-safe status, draft/update without sensitive borrower details. | Agent receives useful status without private data exposure. | Users may overshare to satisfy pressure. | Privacy boundary, clarity, time. | Pass if response is useful and privacy-safe; fail if private borrower data is exposed. |
| SCN-STRESS-010 | Processor finds missing condition | PR-NEW-NTS-01, LO-NEW-NTS-01, LC-EXP-NTS-03 | TERA-CONDITIONS, TERA-NOTIF, TERA-COMMS | Add and route missing demo condition. | Processor review finds missing placeholder condition. | Add condition, assign owner, notify appropriate internal role. | New condition is visible, owned, and not duplicated. | Users may add vague condition or notify wrong person. | Condition clarity, owner, duplicate count. | Pass if condition has owner and next step; fail if duplicate/vague condition is created. |
| SCN-STRESS-011 | Compliance issue on marketing content | IB-MKT-CONTENT-09, IB-COMP-ADCOMM-12, LO-MID-TS-04 | TERA-COMMS, TERA-RBAC | Route demo marketing content for compliance review. | Demo LO content includes risky claim placeholder. | Flag content, route to compliance, block public use. | Risky content is not approved or sent. | Users may miss risk or think draft is approved. | Review accuracy, approval state clarity, recovery. | Pass if content is blocked/routed; fail if it appears approved for use. |
| SCN-STRESS-012 | High volume LO with many active files | LO-VET-TS-06, IB-TL-TS-01, LC-EXP-TS-04 | TERA-DASH, TERA-NOTIF, TERA-STATUS | Prioritize many demo active files. | Dashboard shows many demo files across statuses. | Filter by urgent, owner, status, and next action. | Top risks are identified without losing urgent items. | Filter overload, notification noise, stale status. | Time, missed urgent items, clicks. | Pass if test-script top risks are found; fail if urgent item is hidden or missed. |
| SCN-STRESS-013 | New LO with three files needing help at once | LO-NEW-NTS-01, IB-CC-NEWLO-03, IB-TL-NTS-02 | TERA-DASH, TERA-NOTIF, TERA-CONDITIONS | Help new LO prioritize three demo files. | New LO dashboard shows three urgent-looking tasks. | Identify true priority, route coaching/help, create next action. | New LO knows what to do first and who can help. | All tasks feel equally urgent; user freezes. | Confidence, help needed, priority accuracy. | Pass if correct priority is selected and support path is clear; fail if user cannot choose next action. |
