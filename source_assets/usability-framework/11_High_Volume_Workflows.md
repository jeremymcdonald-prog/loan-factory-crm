# High Volume Workflow Tests

## Purpose

These tests check whether TERA+ supports users who handle many files, requests, or relationships at once. Use fake/demo records only.

| Scenario ID | Workflow | Primary personas | Product OS IDs | Task | Starting point | Expected path | What success looks like | Where users may get stuck | What should be measured | Pass or fail criteria |
|---|---|---|---|---|---|---|---|---|---|---|
| SCN-HV-001 | High producing LO | LO-VET-TS-06, LC-EXP-TS-04 | TERA-DASH, TERA-NOTIF, TERA-STATUS | Prioritize 25 demo active files. | Dashboard contains many fake files across stages. | Filter by urgent, closing soon, conditions pending, and unread alerts. | User identifies top five actions accurately. | Over-filtering, notification noise, stale status. | Time, missed urgent files, clicks, confidence. | Pass if top five match test script; fail if critical file is missed. |
| SCN-HV-002 | Busy processor | PR-EXP-TS-04, PR-EXP-NTS-03 | TERA-CONDITIONS, TERA-DOCS, TERA-DASH | Work a queue of many demo conditions and documents. | Processor queue has many fake open items. | Sort by priority, due date, age, and low-confidence docs. | User identifies next three processing actions. | Dense table, filter confusion, duplicate docs. | Time, errors, missed high-priority items. | Pass if correct next three actions are selected; fail if low-risk task is handled first. |
| SCN-HV-003 | Busy loan coordinator | LC-EXP-TS-04, LC-EXP-NTS-03 | TERA-DASH, TERA-DOCS, TERA-COMMS | Manage many borrower follow-ups. | Coordinator dashboard has many demo follow-up tasks. | Filter by due today, missing docs, LO owner, and urgent alerts. | User creates clean follow-up list without duplicate data entry. | Alert/task overlap and manual tracker habits. | Duplicate entry, time, confidence. | Pass if follow-up list is accurate; fail if duplicate tasks are created. |
| SCN-HV-004 | Team leader managing multiple LOs | IB-TL-TS-01, IB-TL-NTS-02 | TERA-DASH, TERA-STATUS, TERA-CONDITIONS | Review team risk across many LOs. | Team dashboard has many fake LO pipelines. | Sort by stuck files, aging conditions, and LO needing help. | User identifies team-level coaching and escalation priorities. | Dashboard complexity and metric definitions. | Missed risk, confidence, help needed. | Pass if top team risks match test script; fail if dashboard cannot explain priority. |
| SCN-HV-005 | Marketing team managing many LO requests | IB-MKT-CONTENT-09, IB-MKT-AUTO-10, IB-COMP-ADCOMM-12 | TERA-COMMS, TERA-DASH, TERA-RBAC | Triage many content and automation requests. | Marketing queue has many demo LO requests. | Filter by review status, risk, owner, and campaign date. | High-risk content is routed before low-risk edits. | Approval status ambiguity and version confusion. | Review order, risky language missed, duplicate comments. | Pass if compliance-sensitive items are prioritized; fail if public-risk content appears approved. |
| SCN-HV-006 | Business development tracking many candidates or LOs | IB-BD-CANDIDATE-13, IB-BD-RETENTION-14 | TERA-DASH, TERA-COMMS, TERA-RBAC | Review many demo candidate and LO success records. | Dashboard has fake candidate and LO success records. | Filter by stale follow-up, retention risk, and owner. | User identifies top outreach/support priorities without touching borrower files. | Mixing candidate, LO, and borrower contexts. | Record separation, missed follow-up, privacy risk. | Pass if priorities are correct and borrower data remains separate; fail if contexts are mixed. |
