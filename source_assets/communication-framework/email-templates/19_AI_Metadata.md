## Purpose

This file defines the structured metadata AI systems should use to retrieve and recommend the correct email template without reading every template body.

## Metadata Schema

Every `EMT-*` template begins with YAML front matter using these fields: `id`, `title`, `category`, `loan_stage`, `audience`, `loan_programs`, `language`, `priority`, `purpose`, `communication_type`, `workflow_step`, `workflow_trigger`, `automation_trigger`, `automation_timing`, `automation_ready`, `compliance_reviewed`, `recommended_sender`, `recommended_subject`, `required_merge_fields`, `optional_merge_fields`, `required_attachments`, `language_availability`, `search_keywords`, `related_templates`, and `tags`.

`language_availability` means an English master template exists and lifecycle-stage localization modules are available. It does not mean every template has a separately human-approved full translation.

## AI Retrieval Rules

- Prefer exact `EMT-*` ID match when available.
- If no ID exists, match by loan stage, audience, purpose, urgency, and search keywords.
- For borrower-facing sensitive topics, return the template plus the compliance note.
- For Realtor or third-party audiences, filter out borrower-private details.
- For multilingual use, retrieve the English master plus the relevant localization module and translation standards.

## Safety Rules

- AI may draft but should not send.
- AI output must preserve required placeholders.
- AI must not soften conditional approval, pricing, closing, or funding language.
- AI should recommend Manual Only for exception, payment, rate, and closing-delay messages unless a human approves.
